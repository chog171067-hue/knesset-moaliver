# שחזור סיסמה בטלפון (ימות המשיח) - מדריך הפעלה

משתמש ששכח סיסמה מתקשר מהטלפון הרשום בחשבון, מקיש תעודת זהות, מאשר, ושומע
סיסמה זמנית. בכניסה הבאה לקיוסק הוא חייב לבחור סיסמה חדשה לפני שהקיוסק נפתח.

## איך זה עובד

```
מתקשר  ──►  ימות המשיח  ──►  האתר (library-yemot-password-reset)
                              │ 1. מבקש תעודת זהות
                              │ 2. בודק: ת"ז + טלפון רשום = המספר המתקשר?
                              │ 3. מבקש אישור (1 = איפוס, 2 = ביטול)
                              │ 4. מנפיק סיסמה זמנית (6 ספרות, 15 דקות) ומקריא אותה 3 פעמים
                              ▼
עמדת הקיוסק: כניסה עם הסיסמה הזמנית  ──►  מסך "בחירת סיסמה חדשה"  ──►  הקיוסק נפתח
```

### כללי אבטחה

| מה | הערך |
|---|---|
| תוקף הסיסמה הזמנית | 15 דקות, שימוש אחד בלבד |
| ניסיונות כניסה שגויים בעמדה כשיש סיסמה זמנית | 5, ואז היא מבוטלת |
| ניסיונות שלא התאימו מאותו טלפון | 3 בשעה |
| כל הניסיונות מאותו טלפון | 10 ביממה |
| סיסמאות זמניות לאותו חשבון | 3 ביממה |
| מספר חסוי | נדחה (חייבים מספר מזוהה) |
| חשבון מושבת | לא ניתן לאפס |

- **הסיסמה הרגילה לא נמחקת.** הסיסמה הזמנית נשמרת לצידה. אם מישהו אחר ביקש איפוס,
  בעל החשבון ממשיך להיכנס כרגיל, והסיסמה הזמנית פשוט פגה.
- **כל שיחה נרשמת** ביומן, כולל שיחות שנכשלו. היומן מוצג בדף הניהול: קיוסק ספרייה ←
  "שחזור סיסמה בטלפון". מתעודת זהות שלא התאימה נשמרות רק 3 הספרות האחרונות.
- **ההודעה במקרה של אי-התאמה כללית בכוונה.** המתקשר לא יודע אם תעודת הזהות לא קיימת
  או שרק הטלפון לא תואם.
- המספרים בטבלה מוגדרים בראש קטע "שחזור סיסמה בטלפון" בקובץ
  `netlify/functions/lib/kiosk-store.js` (`TEMP_PASSWORD_TTL_MINUTES`, `PHONE_RESET_LIMITS` וכו').

## שלב 1: מפתח סודי בנטליפיי

הכתובת שימות המשיח פונה אליה היא כתובת ציבורית. כדי שרק ימות המשיח תוכל להשתמש בה,
כל בקשה חייבת לכלול מפתח סודי.

1. המציאו מפתח: רצף אקראי של לפחות 30 אותיות באנגלית וספרות, בלי רווחים ובלי סימנים.
   אפשר להיעזר במחולל סיסמאות. לא להשתמש בסיסמה שמשמשת במקום אחר.
2. בנטליפיי: **Site configuration ← Environment variables ← Add a variable**.
3. Key: `YEMOT_RESET_KEY`. Value: המפתח שהמצאתם. שמרו.
4. שמרו את המפתח בצד, כי הוא נדרש בשלב 3.

## שלב 2: פרסום הקוד לאתר

אחרי שהשינויים ממוזגים לענף `main` ב-GitHub, נטליפיי בונה ומפרסם את האתר אוטומטית.
אם הוספתם את המשתנה משלב 1 אחרי הפרסום האחרון: **Deploys ← Trigger deploy ← Deploy site**
(משתנה סביבה חדש נכנס לתוקף רק בפרסום הבא).

**בדיקה:** פתחו בדפדפן את הכתובת
`https://<כתובת-האתר>/.netlify/functions/library-yemot-password-reset`.
צריך להופיע `Forbidden`. זה תקין: הבקשה הגיעה בלי מפתח ונדחתה.

## שלב 3: הגדרת השלוחה בימות המשיח

1. במערכת ימות המשיח, בחרו שלוחה ריקה לשחזור הסיסמה. אם רוצים מספר טלפון ייעודי,
   מפנים אותו ישר לשלוחה הזו.
2. ערכו את קובץ `ext.ini` של השלוחה (בממשק הניהול של ימות: עריכת הגדרות השלוחה), והכניסו:

```
type=api
api_link=https://<כתובת-האתר>/.netlify/functions/library-yemot-password-reset
api_add_0=key=<המפתח משלב 1>
```

- `type=api`: השלוחה מנוהלת על ידי שרת חיצוני (האתר שלנו).
- `api_link`: הכתובת שימות פונה אליה בכל שלב בשיחה.
- `api_add_0=key=...`: מוסיף לכל בקשה את הפרמטר `key` עם המפתח הסודי.

> ⚠️ **חשוב לבדוק:** פורמט הפקודות של ימות המשיח (`read=`, `id_list_message=`,
> `go_to_folder=hangup`, `api_add_0`, והקראת ספרות עם `d-`) נכתב לפי הידוע לנו,
> אבל **לא נבדק מול מערכת ימות אמיתית.** בהתקשרות הראשונה ודאו שכל שלב עובד (ראו
> שלב 5). אם משהו לא עובד, השוו מול המדריך הרשמי של ימות המשיח ל"שלוחת API". כל
> הפקודות נבנות בפונקציות `say` / `askDigits` / `messageAndHangup` בראש הקובץ
> `netlify/functions/library-yemot-password-reset.js`, כך שתיקון נעשה במקום אחד.
>
> אם `api_add_0` לא נתמך במערכת שלכם, אפשר במקומו להוסיף את המפתח לכתובת עצמה:
> `api_link=https://<כתובת-האתר>/.netlify/functions/library-yemot-password-reset?key=<המפתח>`

## שלב 4: עדכון עמדת הקיוסק

1. במחשב העמדה, פתחו PowerShell כמנהל והריצו את סקריפט העדכון הרגיל:
   ```
   powershell -ExecutionPolicy Bypass -File <תיקיית הריפו>\kiosk-app\setup\Update-Kiosk.ps1
   ```
2. **הסקריפט לא משנה את `appsettings.json`**, ולכן צריך להוסיף בו שורה ידנית.
   פתחו את `C:\KioskApp\appsettings.json` בפנקס רשימות (Notepad), והוסיפו את השורה
   `PasswordResetPhone` (שימו לב לפסיק בסוף השורה שלפניה):
   ```json
   {
     "ApiBaseUrl": "https://...",
     "StationApiKey": "...",
     "StationId": "library-station-1",
     "PasswordResetPhone": "02-1234567"
   }
   ```
   במסך הכניסה יופיע: "שכחתם סיסמה? התקשרו מהטלפון הרשום בחשבון למספר 02-1234567…".
   אם משאירים את השורה ריקה או לא מוסיפים אותה, השחזור עדיין עובד, רק בלי ההודעה במסך.
3. הפעילו מחדש את הקיוסק.

## שלב 5: בדיקה מלאה (לפני שמפרסמים למשתמשים)

צרו בדף הניהול משתמש בדיקה עם **מספר הטלפון שלכם**, ואז:

- [ ] התקשרו מהטלפון הזה ← שומעים בקשה להקיש תעודת זהות.
- [ ] הקישו תעודת זהות **שגויה** ← "הפרטים אינם תואמים", והשיחה מתנתקת.
- [ ] התקשרו שוב, הקישו את הנכונה ← "נמצא חשבון מתאים". הקישו 2 ← "האיפוס בוטל".
- [ ] התקשרו שוב, הקישו את הנכונה ואז 1 ← שומעים סיסמה בת 6 ספרות שלוש פעמים.
- [ ] בעמדה: כניסה עם הסיסמה **הישנה** ← עובדת כרגיל, בלי בקשה להחליף.
- [ ] יציאה, וכניסה עם הסיסמה **הזמנית** ← מופיע מסך "בחירת סיסמה חדשה".
- [ ] בחרו סיסמה חדשה ← הקיוסק נפתח.
- [ ] יציאה: הסיסמה הזמנית והסיסמה הישנה כבר לא עובדות, החדשה עובדת.
- [ ] בדף הניהול ← "שחזור סיסמה בטלפון": כל השיחות מופיעות.
- [ ] התקשרו ממספר חסוי ← "לא ניתן לזהות את מספר הטלפון".

## מגבלות ידועות

- **זיוף מספר מתקשר.** הזיהוי מבוסס על המספר שימות המשיח מקבלת, ואת המספר הזה
  אפשר לזייף. מי שמזייף את המספר של משתמש **וגם** יודע את תעודת הזהות שלו יכול
  לקבל סיסמה זמנית. מה שמצמצם את הנזק: הסיסמה הרגילה ממשיכה לעבוד, יש מגבלת
  ניסיונות, הכול נרשם ביומן, והסיסמה פגה אחרי 15 דקות. בחשבון שבו יש רק יתרת הדפסה
  בספרייה, זה סיכון סביר.
- **אין הגבלת ניסיונות על הסיסמה הרגילה בעמדה.** זה היה כך גם לפני השינוי. ההגבלה
  החדשה חלה רק כשיש סיסמה זמנית פעילה. אפשר להוסיף הגבלה כללית בהמשך.
- איפוס סיסמה ידני מדף הניהול (הכפתור הקיים) מבטל גם סיסמה זמנית פעילה, אם יש כזו.
